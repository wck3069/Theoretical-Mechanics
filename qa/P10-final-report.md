# 第五轮：reduced-motion 修复 + M2 俘获判定

## 首页：轨道运动不再被 prefers-reduced-motion 一刀切
- 原代码：`if(!reducedMotion){ updatePlanets(dt); handleShot(now); }`，Windows 关闭“动画效果”时整页只剩静态星图。
- 现改为：
  ```js
  if(!state.paused) updatePlanets(dt);   // 轨道是内容，始终推进
  if(!reducedMotion) handleShot(now);    // 只把流星等装饰留给系统设置
  ```
- `updatePlanets` 内部仍有 `if(state.paused) return;`，并单独用 `reducedMotion` 关闭轨道进动；暂停按钮仍生效。
- 验证：`--force-prefers-reduced-motion` 下 `matchMedia` 为 true，1.2s 与 3.5s 截图**不同** → 行星确实在动。

## M2：吸引势下的俘获判定
- 现象：`-α/r⁴` 吸引势下，b<b_c 的粒子在中心附近被 1/r⁶ 力加速，数值上可能一步跳过中心后被甩出。
- 修复：
  - 解析判定 `willCap = (mode==='capture' && b < b_c)`；
  - 近中心自适应子步进（r<0.8 用 64 子步，r<2.5 用 20 子步）；
  - 俘获吸附：`r<0.18` 或 `(r<0.6 且径向速度向外)` 或速度 >80 → `captureSim()`，位置钳到中心、速度清零、停止积分；
  - 画布显示红色俘获环与“已俘获（b<b_c）”，HUD 同步。
- 确定性验证（直接调用 800 次 `stepTraj()`）：
  - b=0.5、b=1.2（< b_c=1.414）→ `captured=true, x=0, y=0`；
  - b=1.6（> b_c）→ `captured=false`，正常出射。

### M3 几何修正（用户指出：连线必须过质心）
- 原代码恒星取 `y=+r1 sinθ`、行星取 `y=+r2 sinθ`，二者只在 x 上相反，y 同侧，连线不过质心。
- 改为恒星 `y=-r1 sinθ`（主视图、`traj1` 轨道、右上放大图同步），行星保持 `+r2 sinθ`。
- 验证：对整条轨道逐点计算 `traj1 × traj2`，最大叉积 `0.000e+0`（严格共线反向）；等质量双星 `r1=r2=2.6 AU`。
- 视觉模型确认：r1–COM–r2 是一条直线，不是 V 形或偏移线。

# 第八轮：AI 答案公式排版

- 服务端 system/review prompt 限制为简单 LaTeX（禁用 aligned/cases/left/right/mathbb/tag），减少渲染器覆盖不到的情况。
- 视觉模型确认：7 组公式全部正确排版，无 `\frac`/`\sqrt`/`\omega` 原文残留。

# 第十一轮：离线检索的原始 LaTeX 与泛词命中的修复

- 现象：离线回答出现 `\boldsymbol`、`\times`、`\item`、`sub:lorentz`，且“方程”命中 M8/M6。
- 原因：
  1. 这是**离线检索**（标签“离线检索”），不是 AI；页面没有连上 `/api`；
  2. 离线 KB 来自 `.tex`，旧清洗只处理了部分命令，`\boldsymbol`/`\times`/`\item`/裸 `sub:` 残留；
  3. “方程”是泛词，关键词检索命中 M8 Lorentz 与 M6 附录。
- 修复：
  - 重写 `build_offline_kb.py` 的清洗：去 label/ref、begin/end、item、裸 `sub:`/`sec:`；解包 `\boldsymbol/\bm/\vec/\dot/\text/\mathrm/...`；符号表（× · ⊥ ∥ ≤ ≥ ∂ ∇ ∫ Greek…）；去残余命令与花括号。
  - 面板渲染器补 `\boldsymbol`/`\bm`。
  - 离线“方程”输出已无任何原始命令，公式以 `$...$` 交给面板排版。
- 说明：离线模式仍是关键词检索，语义问题请通过隧道/本地服务连接 AI；面板状态应显示“AI 助教在线”。
